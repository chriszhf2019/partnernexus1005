## 一、页面概述

### 1.1 业务目标

「年度营销预算规划」是合作伙伴管理系统中市场营销模块的**核心管控页面**，承担以下业务目标：

1. **预算编制与审批**：制定年度营销预算总额，按 Q1–Q4 四个季度分解，并通过审批流程固化
2. **活动计划管理**：按季度记录和管理市场活动，包括线下峰会、沙龙、Webinar、联合营销等
3. **执行跟踪与偏差预警**：实时监控预算执行率、线索产出与目标偏差，超支/逾期自动触发预警
4. **产出联动与 ROI 评估**：将市场活动与商机管线（Pipeline）联动，量化 ROI 投资回报率
5. **历史修改存证**：所有预算调整和计划修改均留痕，满足合规审计要求

### 1.2 核心价值

| 维度 | 业务价值 |
|------|----------|
| **管理决策** | 预算与执行透明化，季度/年度对比一目了然 |
| **渠道赋能** | 合作伙伴可通过规划页查看自己参与活动的预算、状态与产出 |
| **ROI 量化** | 将市场活动的投入与线索/商机产出量化，避免「拍脑袋」决策 |
| **合规审计** | 修改历史存证 + 预算快照机制，满足财务审计和渠道合规需求 |

## 三、核心功能模块

### 3.1 预算编制与调整

#### 状态机（State Machine）

```
draft ───提交审批───► pending ───批复通过───► approved（锁定）
  ▲                                          │
  │                                          │
  └──────────────重新批复（恢复编辑）─────────┘
                  （保存原因日志）
```

| 状态 | 是否可编辑 | 按钮区 |
|------|-----------|--------|
| `draft`（草稿） | ✅ 可编辑所有字段 | **保存**、**提交审批** |
| `pending`（待批复） | ❌ 只读（提交人除外） | **批复通过** / **驳回** |
| `approved`（已批复/已锁定） | ❌ 只读（季度金额） | **调整预算**（需填写原因）、**重新批复**（回到草稿） |

#### 关键操作：「调整预算」

当状态为 `approved` 时，用户可以通过「调整预算」按钮打开弹窗，修改各季度的 `qX_adjust` 增量值。

**重要约束**：调整后不会改变原来的 `qX_budget` 基线值；只会追加调整量。保存时同时写入 `budget_change_log` 表，记录每次调整的原因和新值。

#### 自动快照（Baseline Snapshot）

当预算从 `pending` → `approved` 时，系统自动向 `plan_baselines` 表写入一条基线快照：

```typescript
{
  year: currentYear,
  field_name: 'annual_budget',
  planned_value: JSON.stringify({
    annual: annualBudget,
    q1: qBudgets[0], q2: qBudgets[1],
    q3: qBudgets[2], q4: qBudgets[3]
  }),
  status: 'active'
}
```

### 3.2 活动计划管理

#### 添加新活动

1. 点击「新增活动」按钮（按季度 Tab 自动填入 `quarter`）
2. 填写活动明细（伙伴、类别、城市、预算、目标等）
3. 保存到 `marketing_plan` 表（`execution_status = 'draft'`）

#### 编辑与保存

- 表格中行为 **行内编辑**（Inline Edit）
- 修改后自动高亮该行，用户点击「保存」按钮批量提交更改至 `marketing_plan` 表
- 保存成功后通过 `justSavedIds` 短暂高亮成功效果（1.5 秒后消失）

#### 提交与批复

- 行内下拉菜单选择「提交审批」将 `plan_status` 从 `draft` → `submitted`
- 管理员「批复通过」操作将 `plan_status` 从 `submitted` → `approved`，同时 `execution_status` → `approved`

### 3.3 凭证管理（合规审计）

每项已执行的活动可上传执行凭证（照片/文件），通过相机图标按钮查看或上传。该功能预留了 **合规审计** 需求，便于财务和渠道合规团队抽查。

### 3.4 年度切换

页面顶部提供年份切换下拉菜单（默认为当前年份，范围 2024 ~ 当前年份 + 1）。切换年份时，所有数据（预算配置、活动计划、修改日志）会重新加载。

### 3.5 智能结转建议

当 `actualSpendQ[Q] < qBudgets[Q]` 时，系统弹出建议信息条：

> "Q1/Q2 剩余资金未使用，建议结转到下一季度 '拉新' 专项"

点击建议条可跳转到「调整预算」弹窗，预先填充结转方向。

### 4.2 数据加载流程

页面加载时，以下 6 个查询 **并行执行**：

```
1. marketing_budget_config → 预算配置
2. marketing_plan (WHERE year = currentYear) → 年度计划
3. budget_change_log (WHERE config_id = 'current', ORDER BY created_at DESC, LIMIT 20) → 修改历史
4. marketing_activities → 实际活动执行（用于回填 actual_spend/leads/opps）
5. partners → 合作伙伴字典
6. mdf_allocations → PMDF 可用额度
```

**数据回填逻辑**：若 `marketing_plan` 中某条计划 `execution_status = 'executed'` 但 `actual_spend` 为空，系统尝试从 `marketing_activities` 中按类别/年份匹配，并更新回数据库。

## 五、核心业务逻辑

### 5.1 预算控制与审批逻辑

#### 总控原则

```
年度总预算 = Σ (Q1~Q4 季度预算 + 季度调整)
```

任何对预算的修改必须经过 **审批锁定制**：

- 只有状态为 `draft` 时允许直接修改季度预算
- 状态为 `approved` 时，只能通过「调整预算」修改 `qX_adjust` 增量，且必须填写调整原因
- 状态为 `pending` 时，管理员可以选择「批复通过」或「驳回」

#### 预算合规校验

| 校验项 | 规则 | 触发场景 |
|--------|------|----------|
| 非负校验 | `qX_budget + qX_adjust >= 0` | 任何保存操作 |
| 年度一致性 | `Σ qBudgets = annualBudget`（允许 1 元容差） | 保存配置时 |
| 批复锁定 | `status === 'approved'` 后，禁止修改 `qX_budget`，只能修改 `qX_adjust` | 编辑操作 |
| 修改原因必填 | `reason.trim().length > 5` | 调整预算弹窗提交 |

### 5.2 投产比（ROI）与联动逻辑

#### 核心公式

```typescript
// 全局预估 ROI
forecastROI = forecastPipeline / annualBudget;  // 结果以 1:xx 形式展示

// 单活动 ROI
roi = actualLeads / (totalBudget / 10000);  // 每万元预算产出的线索数

// 单线索成本
costPerLead = actual_spend / actual_leads;

// 预算执行率
budgetExecutionRate = (actual_spend / approved_amount) * 100;
// 超过 100% 标记为 overrun（超支预警）
// 85%~100% 标记为 warning（接近预算上限）

// 目标线索达成率
targetLeadsRate = (actual_leads / target_leads) * 100;

// 目标商机达成率
targetOppsRate = (actual_opps / target_opps) * 100;
```

#### 漏斗转化逻辑

```
预算投入 ─► 活动执行（参加人数） ─► 线索产出（条数） ─► 商机转化（金额）
```

每个环节均可在表格中查看「计划 vs 实际」对比，系统自动计算达成率并用颜色编码（绿色 = 达标，琥珀色 = 接近达标，红色 = 严重滞后）。

### 5.3 异常预警与偏差逻辑

#### 预警类型

| 预警类型 | 触发条件 | UI 表现 |
|----------|----------|---------|
| 预算超支 | `budgetExecutionRate > 100` | 行内红色高亮 + 表格顶部偏差预警计数 |
| 预算警告 | `85 < budgetExecutionRate <= 100` | 行内琥珀色高亮 |
| 活动逾期 | `execution_status === 'approved' && daysToEvent < 0` | 行内红色标签 + 偏差计数 |
| 即将开始 | `daysToEvent !== null && 0 <= daysToEvent <= 30` | 青色标签（提醒用户筹备） |

#### 时间滚动逻辑

- **过去季度（如 Q1 在 6 月时）**：活动应处于 `executed` 状态，表格只允许查看不允许修改
- **当前季度（如 Q2）**：活动处于 `approved` 或 `executed` 混合状态，可更新执行进度与实际数据
- **未来季度（如 Q3、Q4）**：活动多处于 `draft` 或 `submitted`，可灵活调整计划与预算

### 5.4 季度活动汇总与进度

每个季度 Tab 顶部的汇总卡片展示：

- 活动数（按状态分类）
- 预算总金额
- 预算执行率（actualSpend / approvedBudget）
- 目标线索达成率
- 即将开始 / 逾期数量

## 六、实时计算指标体系（campaignMetrics）

所有**动态指标**集中在 `src/lib/campaignMetrics.ts` 中统一计算，避免 UI 层与业务逻辑的耦合。

### 6.1 数据增强流程

```typescript
// 输入：原始计划行（来自数据库）
PlanRow[] ──► enrichCampaignPlan() ──► EnrichedCampaignPlan[]
                    │
                    ├── 预算执行率、目标达成率
                    ├── 单线索成本 / ROI
                    ├── daysToEvent / isUpcoming / isOverdue
                    ├── campaignPhase / campaignStatus
                    ├── progressPercent（10% → 50% → 100%）
                    └── budgetWarning（normal / warning / overrun）
```

### 6.2 汇总计算

```typescript
// 季度/年度汇总
calculateQuarterlyStats(plans): QuarterlyStats
{
  totalBudget,          // Σ total_budget
  approvedAmount,       // Σ approved_amount
  actualSpend,          // Σ actual_spend
  totalTargetLeads,     // Σ target_leads
  totalActualLeads,     // Σ actual_leads
  executionRate,        // actualSpend / approvedAmount
  leadsRate,            // totalActualLeads / totalTargetLeads
  avgCostPerLead,       // actualSpend / totalActualLeads
  upcomingCount,        // isUpcoming === true 的活动数
  overdueCount,         // isOverdue === true 的活动数
  executedCount,        // execution_status === executed 的活动数
  pendingCount,         // execution_status === approved 的活动数
}
```

### 6.3 维度分布分析

| 分析维度 | 分组键 | 输出指标 |
|---------|--------|---------|
| 按活动类型 | `activity_type` | count / budget / actualSpend / leads |
| 按执行状态 | `execution_status` | count / budget |
| 按区域 | `region` | count / budget / leads |
| 按合作伙伴 | `partner_id` | count / budget / leads |

### 6.4 预警与任务聚合

```typescript
getCampaignAlerts(plans): EnrichedCampaignPlan[]
// 返回所有 isOverdue || budgetWarning === 'overrun' || isUpcoming 的活动

// 返回「正在执行」活动列表（用于待办清单与工作台集成）
```

### 7.3 计算路径

```
plan (原始数据)
  │
  └──► enrichedPlan = enrichCampaignPlans(plan)
          │
          ├──► quarterlyStats = calculateQuarterlyStats(enrichedPlan)
          │       ├──► 顶部 KPI（执行率、总预算、活动数）
          │       └──► 季度汇总卡片
          │
          └──► campaignAlerts = getCampaignAlerts(enrichedPlan)
                  ├──► 偏差预警计数
                  └──► 即将开始/逾期活动标签

actualSpendQ（从 marketing_activities 聚合）
  │
  └──► 预算 vs 实际支出柱状图对比（每季度两根柱）

config
  │
  ├──► qBudgets = qX_budget + qX_adjust（调整后实际预算）
  ├──► annualBudget = Σ qBudgets
  ├──► baseAnnual = Σ qX_budget（不含调整）
  ├──► totalAdjust = Σ qX_adjust
  └──► 饼图 / 进度条渲染
```

### 7.4 状态归一化

页面将 `partners` 以数组形式存储，通过 `partnerMDF` Map 存储伙伴维度的资金信息。这样的设计：

- 支持下拉选择中快速过滤伙伴
- 无需每次渲染时重新计算 MDF 额度
- 避免循环引用和重复计算

## 十、外部集成

### 10.1 与工作台待办清单的集成

- **待办入口**：系统会过滤 `status === 'pending'` 且 `responsible_person` 为当前用户的活动，展示在工作台待办清单中
- **跳转逻辑**：点击待办项直接跳转到 `/marketing/plan` 并自动定位到相关季度 Tab
- **状态同步**：在工作台标记「已处理」后，计划状态在本页面同步更新为 `approved`

### 10.2 与商机管理模块的联动

- `forecast_pipeline` 字段会反向同步到「商机看板」的市场来源统计图表中
- 当营销活动产生商机时，商机表中的 `source_activity_id` 字段会关联到该活动 ID，从而在本页面形成闭环展示

### 10.3 与激励政策模块的联动

- 伙伴级别（Gold / Silver / Bronze）来自激励政策模块的评级计算
- 伙伴 MDF 可用额度（`mdf_allocations`）在下拉选项中作为附加值展示，提示用户伙伴是否有充足的市场发展基金

### 10.4 语言切换

- 页面在中文/EN 双语环境下工作
- 所有状态标签、操作按钮、KPI 指标均支持国际化

## 十一、性能与架构设计考量

### 11.1 计算优化策略

| 场景 | 方案 | 目的 |
|------|------|------|
| 数据增强 | `useMemo(enrichCampaignPlans, [plan])` | 避免每次渲染重复计算 |
| 汇总统计 | `useMemo(calculateQuarterlyStats, [enrichedPlan])` | 依赖更新才重算 |
| 表格行 | `memo()` 包裹每行组件 | 避免兄弟行状态变化导致整表重渲染 |
| 大图表数据 | 分页加载 / 懒渲染 | 初次加载只渲染当前季度 |
| 年度切换 | `Promise.all()` 并行查询 6 个表 | 总等待时间 ≈ 最慢查询的时间 |

### 11.2 组件化分层

```
src/components/marketing/
├── MarketingPlanPage.tsx       ← 主页面（页面级别状态管理）
├── LeadDrilldownDrawer.tsx     ← 线索明细抽屉组件（复用组件）
└── ...
src/lib/
└── campaignMetrics.ts          ← 纯函数计算模块（无副作用）
```

**分层原则**：
1. **页面层**：只处理状态、数据流与用户交互
2. **组件层**：无业务逻辑、只接收 props 渲染
3. **工具层**：纯函数，输入 → 计算 → 输出（无 React 依赖）

### 11.3 错误处理

| 场景 | 处理方式 |
|------|----------|
| 网络失败 | Toast 提示 + 显示「重新加载」按钮 |
| 数据空 | 友好空状态 + 引导用户创建第一个计划 |
| 权限不足 | 展示只读视图 + 提示「需管理员权限」 |
| 保存冲突 | 检测到并发更新时，提示「数据已过期，刷新后重试」 |
